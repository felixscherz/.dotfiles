# Search

Build enough shared understanding to define the task or resolve a specific uncertainty. Search can begin a task or
answer a question routed from another phase.

## Inputs

Read the user's intent, available project context, and any existing task, findings, or reconciliation question.
Inspect relevant sources before asking the human for facts already available there.

## Work

Explore the problem, affected users or systems, desired outcome, current behavior, constraints, and non-goals.
Separate observed facts from assumptions and unresolved questions. Compare materially different approaches when
the choice affects the result. Make recommendations with reasons; do not force a design before the problem is clear.

For a routed investigation, answer the question that caused the return to Search. Do not reopen settled decisions
without new evidence. If an exploratory experiment is useful and authorized, distinguish it from accepted production
implementation and record what it established.

Capture consequential context and decisions in the task draft, or in a finding's investigation record for an active
agreement. Search cannot alter an approved requirement through a context note.

## Exit and handoff

State what is known, what remains uncertain, and whether there is enough information for the next decision.
Move to Plan for a new or revised agreement. If investigation confirms that the agreement remains adequate, return
through reconciliation to the responsibility that can now proceed.

When the user requested Search only, end with durable context and the proposed next step. When Search and Plan were
requested together, read the Plan reference and continue without an unnecessary session boundary.
